# SEOGEO v1.0

웹사이트의 기술 SEO, AI 검색 노출 준비도, GEO, E-E-A-T, Schema.org, Bing/AEO 요소를 한 번에 점검하는 React 기반 분석 도구입니다.

v1.0은 기업 홈페이지 진단에 집중하며 **SEO 기반 품질 · AI 검색 가시성 · 네이버 노출 기반**을 독립적으로 분석합니다. 실제 검색 기능을 지원하는 AI 엔진에는 고정 질의를 실행해 GEO 변화를 추적합니다.

## 주요 기능

### 홈페이지 SEO·GEO 진단
- URL을 직접 수집해 SEO 신호 분석
- Sitemap과 내부 링크를 이용한 최대 50페이지 사이트 크롤링
- 사이트 전체 Health Score와 중복·누락·오류 페이지 진단
- 규칙 기반 점수와 선택적 Gemini 분석
- 사이트별 점수 비교와 개선 체크리스트
- 키워드 및 메타 태그 최적화 도우미
- robots.txt, 구조화 데이터, 분석 도구 설치 여부 확인
- 메뉴별 독립 점수·최우선 액션·개선 체크리스트
- SSRF 방어와 기본 요청 제한

### GEO 모니터링 — AI 인용률 실측
- **검색 기반 엔진**: Perplexity, OpenAI Web Search, Gemini Search Grounding
- **참고·베타 엔진**: Claude 일반 응답, 네이버 HyperCLOVA X
- **실제 인용 URL 추출**: 검색 기반 API가 반환한 출처 URL 사용
- **반복 측정(1/3/5회)**: LLM 비결정성을 완화하고 인용률을 %로 산출, 신뢰도 표시
- **브랜드 동의어 등록**: 브랜드를 다르게 부르는 표기까지 감지
- **인용 문맥 표시**: 브랜드가 언급된 전후 문장을 그대로 확인
- **개선 액션 추천**: 인용률과 약한 엔진에 맞춘 우선순위별 실행 방안
- **질의 자동 생성**: Claude가 브랜드·업계 맥락에 맞는 질의를 카테고리별로 생성
- **전후 비교 리포트**: 두 측정을 비교해 Markdown 복사 또는 HTML·PDF로 저장

## 실행 방법

Node.js 20 이상을 권장합니다.

```bash
npm install
npm run dev
```

기본 개발 주소는 `http://localhost:5173`입니다.

## 환경 변수

`.env.example`을 `.env`로 복사한 뒤 필요한 키만 채우면 됩니다. `.env`는 `.gitignore`에 등록되어 있습니다.

```bash
cp .env.example .env
```

| 변수 | 용도 | 없을 때 동작 |
| --- | --- | --- |
| `GEMINI_API_KEY` | SEO AI 분석 · GEO(Gemini) | 규칙 기반 분석만 실행 |
| `PPLX_API_KEY` | GEO(Perplexity) | 해당 엔진 미측정 |
| `OPENAI_API_KEY` | GEO(ChatGPT) | 해당 엔진 미측정 |
| `ANTHROPIC_API_KEY` | GEO(Claude) · 질의 자동 생성 | 해당 엔진 미측정, 질의 생성 비활성 |
| `NAVER_CLOVA_API_KEY` | GEO(네이버 HyperCLOVA X) | 해당 엔진 미측정 |

GEO 모니터링은 키가 설정된 엔진만 측정합니다. 전부 선택 사항이며, 하나도 없으면 SEO 준비도 진단만 사용할 수 있습니다.

네이버 키는 [CLOVA Studio](https://clovastudio.ncloud.com)에서 테스트 앱을 만든 뒤 발급받습니다(`nv-`로 시작).

운영 환경에서는 API 키를 브라우저에 저장하거나 입력받기보다 서버 환경 변수로만 관리하는 것을 권장합니다.

## GEO 모니터링 사용 순서

1. `GEO 모니터링` 탭에서 타깃 도메인과 브랜드명을 입력합니다.
2. 브랜드 동의어를 등록하면 감지 정확도가 올라갑니다.
3. 질의를 직접 추가하거나 `AI로 질의 6개 자동 생성`을 누릅니다.
4. 측정할 엔진과 반복 횟수를 고릅니다. **추세를 판단하려면 3회 이상을 권장합니다.**
5. 측정 후 개선 작업을 적용하고 다시 측정하면 전후 비교 리포트가 나타납니다.

> 인용률은 AI 응답에 브랜드·도메인이 등장하는 비율을 측정한 자체 지표이며, 각 AI 서비스의 공식 노출 지표가 아닙니다. 같은 질의도 응답이 매번 달라지므로 1회 측정 결과의 변화는 노이즈일 수 있습니다.

```bash

```

## 배포

`vercel.json`과 `/api` 서버리스 함수를 포함하고 있어 Vercel 배포를 기본 대상으로 합니다.

배포 환경에도 위 표의 환경 변수를 동일하게 등록해야 합니다. 등록하지 않은 엔진은 프로덕션에서도 측정되지 않습니다.

서버리스 함수는 `api/analyze.ts`, `api/insight.ts`, `api/geo-monitor.ts`, `api/geo-expand-queries.ts` 네 개이며, 개발 서버에서는 `vite.config.ts`의 미들웨어가 같은 경로를 동일한 형식으로 처리합니다. **API 경로를 추가할 때는 두 곳을 함께 수정해야 합니다.**

GEO 모니터링은 `질의 수 × 엔진 수 × 반복 횟수`만큼 외부 API를 순차 호출하므로 실행이 길어질 수 있습니다. `api/geo-monitor.ts`의 `maxDuration`은 300초로 설정되어 있으며, Vercel 요금제에 따라 상한이 다릅니다.

## 주의사항

- 점수는 검색엔진의 공식 순위 점수가 아니라 측정 가능한 신호를 바탕으로 한 진단 지표입니다.
- JavaScript 렌더링 이후에만 나타나는 콘텐츠는 일부 누락될 수 있습니다.
- 외부 사이트의 차단 정책이나 네트워크 상태에 따라 수집 결과가 달라질 수 있습니다.
- 사이트 크롤링은 기본적으로 최대 50페이지, 링크 깊이 3단계까지 분석합니다.
- 실제 검색 노출을 보장하지 않으며 개선 우선순위를 정하는 참고 자료로 사용해야 합니다.

제품 범위와 판매 전 출시 조건은 [docs/V1.0-PRODUCT-RELEASE.md](docs/V1.0-PRODUCT-RELEASE.md)를 참고하세요.

## v0.2 사이트 진단 기준

- 기본 범위는 최대 50페이지, 링크 깊이 3단계이며 sitemap과 내부 링크를 함께 탐색합니다.
- robots.txt의 Allow/Disallow 규칙을 지키며, 차단되어 제외된 URL 수를 결과에 표시합니다.
- Site Health Score는 `site-health-v0.2.0` 규칙으로 계산됩니다. 문제별 최대 감점, 영향 페이지 비율, 실제 감점값을 확인할 수 있습니다.
- 같은 사이트를 다시 검사하면 이전 결과와 비교해 점수 변화, 해결된 문제, 새로 생긴 문제를 표시합니다.
- 각 문제에는 수정 방향과 재검사 방법이 함께 제공됩니다.
- 이 점수는 검색엔진의 공식 순위 점수가 아니라 기술 SEO 문제의 우선순위를 정하기 위한 진단 지표입니다.
